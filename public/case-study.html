About the demo
To keep it free to run, the public demo serves one pre-generated sample story through the same flow; the AI pipeline runs when API keys are set.

The challenge

Build a paid consumer product where every unit of work costs real money: each story calls three AI providers (text, images and voice). That meant the hard parts were not only the features, but making the product fast, safe to expose publicly and impossible to run at a loss, even for a customer who uses every story they pay for.

What I built

  • Story pipeline. Claude writes a 6-page story as structured JSON. Gemini first paints a character sheet of the pet and then every scene with that sheet as a reference, so the pet stays consistent. ElevenLabs narrates each page in four voices, streamed to the browser while it is generated and cached by content hash so no page is ever paid for twice.
  • No dead waiting time. Illustrations take about a minute, so they are painted in the background; the story opens as soon as the first pages are ready, and a pet-trivia quiz with a streak record fills the wait.
  • Accounts without passwords. Email one-time codes and Google sign-in with a nonce-protected ID-token flow.
  • Monetisation. Two tiers, monthly or yearly, each with monthly and daily caps, a 3-day free trial, one-off story packs, in-app upgrades with proration and a "start my plan now" button.
  • Sharing. Public read-only story links with rich previews, and a 1080×1920 image for Instagram Stories rendered on a canvas in the browser.

Key decisions

  • No framework. A plain node:http server (~550 lines) and vanilla JS gave full control over headers, streaming and caching, with no build step and a very light first load.
  • The database is closed to the browser. Row-level security is on with no policies; only the server, with the service role, can read or write. Credits are spent through SECURITY DEFINER functions that public roles cannot execute, so two parallel requests can never spend the same story.
  • Webhooks that cannot go wrong. The server re-fetches each subscription from Stripe instead of trusting the event payload, ignores events for older subscriptions and records each purchase once. A late or duplicated event never grants or removes access by mistake.
  • Pricing designed from unit economics. I modelled the cost of a story (≈ €0.34) and sized every cap so the worst case still leaves a margin after VAT and fees. Yearly plans grant stories month by month from the billing anniversary, with month-end edge cases covered by tests.

Performance

I measured first, then fixed what weighed most. The biggest win was not on the landing page: each AI illustration was a ~740 KB JPEG. Converting them to WebP on save (with lazy migration of old ones) cut them to ~123 KB, six times smaller with no visible difference.

Other changes: content-versioned asset URLs with one-year immutable caching, ETag and Brotli, variable fonts (6 files → 2) and lazy loading of non-critical modules.

Security and reliability

  • Strict CSP and security headers, per-IP rate limiting, request timeouts and validation on every route, with integration tests that boot the real server and try path traversal and malformed input.
  • Graceful shutdown: on deploy the old instance finishes in-flight requests and running illustration jobs before exiting, behind health checks, for zero-downtime releases.
  • CI on every push (syntax, tests, dependency audit); the host only deploys green builds. Nightly AES-256-encrypted database backups, uptime monitoring and spend limits on every AI provider.

What I learned

  • With AI products, cost is part of the architecture: caching, limits and idempotency decide whether the business works.
  • Measuring before optimising pays off: the biggest performance problem was somewhere I did not expect.
  • Payment flows are mostly about the unhappy paths: declined cards, duplicated or late webhooks, and users who change plans halfway through a period.

Next steps I would take

Gift cards and discount codes, lifecycle emails (welcome, trial ending, re-engagement), an internal metrics dashboard with AI cost per story, and an English version of the product.
